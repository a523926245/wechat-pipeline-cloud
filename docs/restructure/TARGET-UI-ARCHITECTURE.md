# 目标导航、页面结构与交互规范

**日期**：2026-11-12 | 消化 UI-UX-REDESIGN-PLAN + 本次源码诊断后的**收敛版**（差异处以本文为准，理由随附）

---

## 7.2 目标信息架构（导航）

```text
工作台（Dashboard）              ← 所有角色；待办队列+质量概览+系统健康
内容生产
  ├─ 选题中心（一级入口！）       ← 候选/待改/正式/已用/拒绝 五 Tab
  ├─ 创作计划（排产+任务队列）
  └─ 文章工作台（状态 Tab → 文章编辑工作区）
内容策略
  ├─ 赛道管理
  ├─ 形态契约（结构化编辑 + 高级 JSON + 版本 diff）
  └─ 全局创作原则（global + PromptVersion 发布/回滚）
质量中心
  ├─ 选题质量   ├─ 文章质量   └─ 事实核验
AI 运行中心（只管"每次调用发生了什么"）
  ├─ 调用记录   ├─ 失败分析   └─ Prompt 追溯
运营与系统
  ├─ 公众号账号  ├─ 自动调度  ├─ 模型配置  ├─ 用户与权限  └─ 其他系统配置
```

（2026-11-12 用户归并定稿：**模型配置归运营与系统**——管连接/角色/参数；**AI 运行中心专注运行记录**——管每次调用的事实。两者职责不同。）

与 UI-UX-REDESIGN-PLAN 的差异（我的收敛）：
1. 它把"运行记录/Prompt 追踪"放在运营与系统下——我提升为独立「AI 运行中心」，因为 GenerationRun 是高频排障面（对应后端新表）。
2. 它的"内容契约/文章表达配置"合并两页——我拆「形态契约」（数字/结构）与「表达」（文风/变体）两页，与后端 L1/L2 分层一一对应，**UI 结构镜像数据结构**。
3. **RBAC 重定**〔必须先拍板〕：member（客户）应能看到**自己归属**的选题/文章审核流；guest 只读文章。现在 member 无选题入口是产品缺陷。前端显隐继续不作为安全边界（沿用后端 requirePermission）。

## 7.3 交互规范（浓缩，落地细则随 P0 设计系统文档）

| 环节 | 规范 |
|---|---|
| 页面骨架 | 壳层顶栏=面包屑+全局状态+用户；页内 wb-page-head=标题+一句用途+主操作（**去重标题**）；主内容单滚动容器 |
| 列表/筛选 | 筛选存 URL（沿用）；批量操作条仅勾选后出现（BatchBar 范式）；行内主操作 1 个+更多菜单；长文本列截断+详情侧栏 |
| 表单/配置 | 分组表单或步骤式；实时校验（含算术校验错误指到字段）；未保存拦截（沿用 buf/saved 范式）；数字输入框而非自由文本 |
| 详情 | 侧栏抽屉（列表页）/ 独立工作区（编辑页）；内容型信息（选题质量报告、审核意见、证据）用卡片流不用表格 |
| 状态流转 | 统一状态徽标（文字+色，不只靠颜色）；状态机由后端 API 驱动，UI 不自造状态；非法流转按钮禁用+原因 |
| 批量操作 | 前置显示影响条数；危险操作二次确认文案含范围与可恢复性；批量审核只对"无硬性风险"项开放 |
| 反馈 | 成功=轻 Toast；失败=保留上下文+重试；**AI 长任务=页面内进度条+可离开+结果入口**（扩库/写稿/封面/审核都算）；保存四态（未保存/保存中/已保存/失败） |
| AI 操作披露 | 每个 AI 按钮就近说明：输入什么/产出什么/是否落正式数据/是否可撤销/可能消耗模型额度 |
| 版本与历史 | 形态契约、Prompt、审核记录均提供 diff 与回滚入口；修改追踪=修订号（round） |
| 空/错/加载 | 空态给下一步动作（如"候选为空→去生成"）；错误态=StateError 统一组件；骨架屏不整页白屏 |
| 可访问性 | 键盘焦点可见、弹窗焦点管理、触控 ≥24px、状态不只靠色（UI 方案 6.5 直接采纳） |

**高频复杂操作的专门范式**（不能当普通 CRUD）：
- **选题审核**：左列表（可键盘 j/k）+ 右详情（质量六维条、风险红标、相似选题并排 diff、通过/改后通过/拒绝/标重复）+ 批量模式（只过"无风险"项）。
- **文章审核**：编辑工作区右侧面板（lint error/warn 分组、点击问题→滚动定位段落 blockIndex、修改建议一键转定向修改指令）。
- **形态契约配置**：结构化表单（rhythm 下拉、sections/chars 数字区间、subjects 列表编辑）+ 实时算术校验提示（"12 主体×74 字+5 场景=1258 < 下限 1300，不成立"）+ 发布/草稿版本 + Diff。

## 7.4 视觉设计方向（收敛版）

- **风格**：编辑部工作台（AI Editorial Studio）——专业、安静、内容优先；不搞 AI 科技风/玻璃拟态/发光边框。（采纳 UI 方案 2.1-2.2）
- **色彩**：沿用 `--wb-*` 令牌；**主色 #0a7c47 是品牌硬约束不可改**；把 styles.css:61 起的"品牌扩展令牌"（渐变等）并回基础令牌或删除，消灭双令牌体系。状态色语义化（success/warning/danger/info），涨跌等金融规约不适用本产品。
- **字体**：系统栈；层级 5 档（页面标题/模块标题/正文/辅助/数据数字）；正文阅读宽度 ≤72ch（选题/文章长文区）。
- **间距**：4/8/12/16/24/32 沿用 --wb-space-*；圆角两档（控件 6px/面板 10px，已有）。
- **表格/卡片**：管理字段走表格，内容型走卡片+侧栏；不做卡片墙。
- **深色**：沿用 useTheme；P0 阶段逐页过一遍边框/禁用态/编辑器（UI 方案已列）。
- **动效**：≤200ms，尊重 prefers-reduced-motion。

## 7.5 UI/UX 实施边界（什么能先做、什么必须等后端）

| 类别 | 内容 | 依赖 |
|---|---|---|
| 纯视觉优化（**可立即独立做**） | 双令牌合并、标题去重、深色逐页校对、状态徽标统一、空/错/加载三态全覆盖、响应式修缮 | 无 |
| 信息架构调整（**可立即做**，用现有 API） | 导航重排（选题中心一级入口=TrackAngles 汇总页）、Dashboard 待办区（现有数据）、表单分组 | 现有 API 足够 |
| 交互流程重构（部分依赖后端） | 选题审核工作流、文章状态 Tab、编辑器可视化模式、AI 任务进度组件 | 状态机 API（阶段 2/4） |
| 前后端配合改造 | 形态契约编辑器（schema 校验接口）、版本 diff、Review 面板、运行记录页、段落定位 | 阶段 1/3/4 新表新端点 |
| 新增业务能力 | 质量中心指标、事实核验中心、Trace 追溯链 | 阶段 3-5 |

**排序铁律**（采纳 UI 方案 §0 + 用户裁定）：先 P0 设计系统+壳层（无后端依赖，可与后端阶段 1 并行）→ 页面改造按后端能力就绪顺序滚动 → **不允许假数据/空壳状态上线**（"审核中"等状态必须来自真实 API）。

### UI 三批次（2026-11-12 用户定稿）

| 批次 | 页面与能力 | 可否提前 |
|---|---|---|
| **P0** | 设计系统、导航、壳层、标题去重、暗色模式、统一三态 | 可以（阶段 0） |
| **P1** | 选题中心、契约配置、编辑工作区的**结构原型** | 可做原型；真实状态依赖 API |
| **P2** | 审核、质量中心、运行中心、事实核验 | 跟随后端 API 实施（阶段 2-5） |

**真机浏览器走查**：设为**阶段 0 设计系统验收前必须完成**（不阻塞架构设计，但不允许仅凭静态分析宣布 UI 验收通过）。走查范围：Dashboard、选题、文章编辑、文风/契约配置、模型配置、暗色模式、窄屏。

### 统一 AI 任务中心（用户补充的重要能力）

AI 扩充选题 / 生成文章 / 批量审核 / 生成封面 / 事实核验——**不允许全部做成"点击按钮等接口返回"**。任务组件至少支持：排队中 / 执行中 / 成功 / 失败 / 取消（仅当后端真支持）/ 查看结果 / 查看失败原因。任务离开页面后仍可查询状态（依赖后端持久化任务 ID 与状态，复用 TaskRun/GenerationRun），不能只用前端 loading 假装任务还在跑。落地形态：`AppTaskProgress` + 全局任务抽屉 + 任务中心页（阶段 4/5 随 GenerationRun 上线）。
