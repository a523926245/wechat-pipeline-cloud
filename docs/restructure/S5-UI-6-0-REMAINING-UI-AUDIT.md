## 5. P0/P1/P2/P3 问题清单与证据

### 【本轮新发现 · P1】成员角色无法保存自己的自动化模式（核心功能阻断 + 反馈误导）
- **链路/页面**：流程 D；`web/src/views/SchedulerView.vue:74`（saveCfg）、`:35`（cfg 定义）；后端 `server/src/api/routes/scheduler.ts:90-94`。
- **复现**：以 member 登录 → 自动调度页 → 改「自动化模式/写稿时间」→ 点「保存配置」。
- **当前表现**：必然失败并提示「全局调度开关仅管理员可改」，但用户没碰全局开关。根因：前端提交 `{...cfg, automationMode, writeTime}` 把 `enabled`/`pushEnabled`（cfg :35 初始化）一并带上；后端只要 body 含这两个键（**不论值是否变化**）且非 admin 就抛错。→ **P4「每客户自动化模式」对 member 完全不可用**。
- **预期**：member 提交只含 `automationMode`/`writeTime`，能正常保存自己的模式。
- **影响**：核心自动化配置成员无法完成，错误文案误导排查。
- **级别**：**P1**。修复建议：前端按角色构造 payload（member 只发个人字段），或后端 globalPatch 只对**值真正变化**的全局字段校验。需后端配合（最小可前端先做）。
- **证据类型**：源码交叉确认（前端 payload + 后端校验），**浏览器未实测**（只读授权）。

### 【本轮新发现 · P2】自动调度 dry-run 横幅用错信号，与实际推送相反
- **链路/页面**：流程 D；`web/src/views/SchedulerView.vue:219-226`；后端 `server/src/services/scheduler.ts:34-35,214,289,333`。
- **复现**：全局 `pushEnabled=false`（并行期默认）时，某账号设 `auto_draft_push` → 打开自动调度页。
- **当前表现**：横幅固定显示「当前为 dry-run：调度会写草稿，但不会推送到公众号」（条件 `cfg.enabled && !cfg.pushEnabled`）。但后端推送按**每账号** `mode==='auto_draft_push'` 决定（:289/:333），`pushEnabled` 早已降级为"无主账号兜底"（:34-35/:214）→ 横幅说"不会推"，实际会推草稿箱。
- **预期**：横幅按当前用户实际 `automationMode` 判断，仅 `manual`/`auto_draft` 才提示 dry-run；或改文案说明全局开关只影响兜底。
- **影响**：对"是否自动推送"给相反反馈；仅进草稿箱不群发、无严重后果。
- **级别**：**P2**（反馈误导，有替代理解路径）。证据类型：源码交叉确认，浏览器未实测。

### 【历史遗留 · P2，S5-UI-4-0 已登记未闭环】
- **B-1 出稿前置确认/AI 披露**：`PlanView.vue` 现有 confirm 都是**出稿后**结果确认（:100/:114/:135），触发前无"消耗额度/落草稿可改/账号与篇数"说明。S5-UI-4-0 列为 P2 并建议 4-1 修，但 4-1-A/B/C 未覆盖。**非本轮新发现**，如实标注未闭环。
