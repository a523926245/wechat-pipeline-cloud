# 写作链路（Writing Pipeline）

> 状态：2026-11-12。本文描述**当前实际生效**的写作逻辑，供后续深入优化时对照。
> 与 `docs/WRITING-GUIDE.md` 的分工：那份是**写作方法论**（怎么写出好文章），
> 这份是**工程链路**（一篇文章从选题到草稿箱，经过哪些代码、读哪些配置、在哪一层可以改）。

---

## 1. 全景

```
选题（Angle 表）
   │  angles.ts: expandAnglesForTrack() 扩库 → topicRejectReason() 守门
   ▼
调度（scheduler.ts: tick 每分钟）
   │  到点 → planner.ts 排产 → 取一个未用 Angle
   ▼
写作（writer.ts: generateDraft）
   │  1. loadStyleForTrack()  读该赛道的 5 类配置
   │  2. pickVariants()       按游标取「结构卡 / 标题公式 / 篇幅档」各一
   │  3. buildPrompt()        user 消息：赛道文风 + 写作规范 + tail(选题/变体/篇幅)
   │     buildSystemPrompt()  system 消息：结构 + 硬性禁令 + 引用出处
   │  4. chatComplete()       调 LLM 出 HTML
   │  5. postProcess()        确定性后处理（强调 → 段落重排）
   │  6. lintArticle()        体检；不过 → repairOnce() 定向修补（≤2 轮）
   ▼
落库（Article 表，status=draft）
   ▼
推送（publisher.ts: pushArticleToDraft）
      · 再跑一次体检（同一套规则，门禁）
      · 只写微信草稿箱，**绝不群发**（AUTO_PUBLISH 恒 false）
```

三个自动化层级要分清（`scheduler.ts`）：

| 模式 | 含义 |
|---|---|
| `manual` | 纯手动 |
| `auto_draft` | 到点自动写稿入库，人工审后手动推 |
| `auto_draft_push` | 到点自动写稿并**推到草稿箱**（仍不是群发） |

## 2. 配置真源：`StylePrompt` 表

**运行时只读这张表**。`config/style_dna.json` 已停止参与运行时（文件里加了 `__deprecated__` 说明），
出厂默认值在 `server/src/services/style-prompts.ts` 的四个常量里：
`DEFAULT_GLOBAL_PROMPT` / `DEFAULT_TRACK_PROMPTS` / `DEFAULT_TRACK_SPECS` / `DEFAULT_VARIANT_LINES` /
`DEFAULT_TRACK_RULES`（在 `track-rules.ts`）。

| key 形态 | 含义 | 格式 | 谁读 |
|---|---|---|---|
| `global` | 创作总纲 | 纯文本，跨赛道唯一共享项 | 写稿 + 扩库 |
| `{赛道名}` | 赛道文风 | 纯文本，「字段：内容」一行一条 | 写稿 |
| **`sys:{赛道}`** | **系统提示词（决定「文章长什么样」）** | `## system` + `## tail` 两节，含 `{{变量}}` | 写稿 |
| `v:{赛道}:title` | 标题公式 | 多条，`---` 分隔（单行时可一行一条） | 写稿（轮换） |
| `v:{赛道}:structure` | **结构骨架卡** | 多张卡，`---` 分隔，每张 4-8 行 | 写稿（轮换） |
| `v:{赛道}:length` | 篇幅档 | 一行一档：`字数区间\|段数锚\|说明` | 写稿（轮换） |
| `s:{赛道}` | 写作规范 | 用 `## 段落形态` / `## 强调标注` / `## 句式补充` / `## 去AI味（预留）` 分节 | 写稿 |
| `r:{赛道}` | 机器规则 | JSON：`{ checks: string[], angleMode, relax?: string[] }` | 体检 + 选题 |

> **分层关系**：`sys:{赛道}` 管「形态」（这是一篇清单文还是群像文），`{赛道名}` 管「语气」
> （用什么口吻说话），`v:` 管「这一篇用哪个骨架」，`s:` 管「段落与强调的细部纪律」。
> 2026-11-12 之前没有 `sys:` 这一层，六条赛道共用一份写死的 system，
> 于是「文风能换、骨架换不掉」——星座稿和育儿稿最后长成了同一种情感散文。

### 2.1 结构骨架卡（本次改造的核心）

一张卡 = 一套节结构，要写清「分几节 / 每节干什么 / 写哪几个 / 段数」：

```
骨架｜对号入座型 · 切片清单
第一节：一个具体场景（时间 + 地点 + 一句对话），先不点星座
第二节：6 个行为切片，每段一个星座的一个具体动作；星座名放段末，不放段首
第三节：写一个「看起来像 A 座其实是 B 座」的反例，或一个被误会的瞬间
第四节：收尾，回扣开场场景，问读者「你是第几个」
共 3-4 节 · 至少点名 4 个不同星座 · 六个切片不许用同一种句式
```

**为什么必须是多行**：改造前结构变体只能写一句话（40 字），模型拿不到「每节干什么」，
只能自己发挥，最后套上通用骨架——这正是「星座稿写成职场文」的直接原因之一。

### 2.2 写作规范（`s:{赛道}`）

按 `## ` 切小节，**逐节单独注入**（不是整段塞进去）。默认三节 + 一个预留：

```
## 段落形态     ← 段落是场面单位、3-5 句 60-140 字、禁止一句一段、小标题下不先写总结
## 强调标注     ← 全篇 8-12 处加粗、红字 2-3 处、哪些不该加粗
## 句式补充     ← 本赛道额外禁忌（星座：不做歧视排序、不预言具体事件…）
## 去AI味（预留）← 当前不生效，见第 8 节
```

### 2.3 篇幅档格式

`字数区间|段数锚|说明`，例：`1800-2200|17-19|标准型：分星座展开，每个配一个具体场景`

- 解析失败会被**静默忽略**，写稿回退默认锚（`constants.ts` 的 1800-2200 / 17-19）
- 所以配置页会提前校验并标红

### 2.4 系统提示词（`sys:{赛道}`，2026-11-12 新增）

一份模板，按 `## ` 分两节：

```
## system
你是什么赛道的写手 / 这篇文章的形态 / 结构 / 禁项
## tail
这次怎么写 / 自检清单
```

- `## system` 进 system 消息；`## tail` 拼在 user 消息末尾（tail 永不被预算截断）
- 回落顺序：`sys:{赛道}` → `sys:default` → 代码种子。
  **赛道那一行删掉 = 改用通用模板**，所以要删除就真的能删掉，不会被代码复活
- 变量（渲染时替换，见 `writer.ts: renderTemplate`）：
  `{{minSections}}` `{{maxSections}}` `{{targetMin}}` `{{targetMax}}`
  `{{minChars}}` `{{maxChars}}` `{{pMin}}` `{{pMax}}`
- **数字必须走变量**：写死「5 个小标题 / 2000 字」会和推送门禁打架。
  模板里一个数字变量都没写时，代码在末尾补一行硬锚（`anchorLine`），保证门禁指标传达到模型
- 未定义变量**原样保留**（不会被替换成空），并在日志里 warn——配置页把 `{{pMin}}` 写成
  `{{pmin}}` 时，prompt 里能一眼看见漏网的那个

## 3. Prompt 怎么拼

### 3.1 user 消息（`buildPrompt`）

顺序即优先级，**后面的不会被截断**（tail 永远完整保留）：

| 序 | 块 | 来源 | 是否受预算 |
|---|---|---|---|
| 1 | `【创作总纲（硬性）】` | `global` | 是 |
| 2 | `【本赛道文风（硬性）】` | `{赛道}` | 是 |
| 3 | `【写作规范 · 段落形态】` | `s:{赛道}` 该节 | 是（整块规则） |
| 4 | `【写作规范 · 强调标注】` | 同上 | 是（整块规则） |
| 5 | `【写作规范 · 句式补充】` | 同上 | 是（整块规则） |
| 6 | **`【本次变体】`** | `v:{赛道}:*` 各取一条 | **否（tail）** |
| 7 | 选题主题 / 角度 | Angle | **否（tail）** |
| 8 | **收尾指令（`## tail` 渲染结果）** | `sys:{赛道}` | **否（tail）** |

### 3.2 预算规则（改这里之前先读）

- `MAX_BRIEF_CHARS = 7600`（`writer.ts`），只约束**规范区**，tail 不算在内
- `MIN_BLOCK_COMPLETENESS = 0.6`：某块能放下的比例 **< 60% 就整块丢弃**，并 `logger.warn` 报账
- 为什么这样设计：过去是「超了就切尾巴」，产出的是**半截指令**（有标题没内容，或者条件写一半）。
  实测 6800 预算下「强调标注」只注入 510 / 原文 900+，「直接在 HTML 里标 `<strong class="key">`」
  这条最可执行的指令**整条丢失**。半截指令比没有更糟——模型会当它不存在。

### 3.3 system 消息（`buildSystemPrompt`）

**2026-11-12 起内容不在代码里**：整份 system 提示词来自 `sys:{赛道}` 的 `## system` 节，
代码只做三件事——取模板、填数字变量、模板漏写数字时补硬锚。

改造前这里有 12 条写死的规则，六条赛道共用。那份内容本身就是一个完整文体规格
（复合长段落 / 禁一句一段 / 结尾回扣物件 + 第二人称提问），所以无论赛道文风怎么写，
产出都是同一种情感散文。**这 12 条现在只作为 `sys:default` 的兜底内容存在。**

各赛道的 `## system` 现在各自定义形态，差异落在这些地方：

| 赛道 | 形态 | 段落节奏 | 结尾 |
|---|---|---|---|
| 星座 | 群像切片，9-11 个星座各一段 | 中短段，一个星座一段 | 截图句 /「你是第几个」 |
| 育儿 | 反常识 + 四拍清单 | 允许一句一段 | 可转发到家庭群的一句话 |
| 职场 | 冲突 + 一条判断 + 5-7 条自测 | 混合（长场景 + 短判断） | 一句截图话 +「你占了几条」 |
| 教育 | 引原话 + 替家长提问 + 三步搞懂 | 混合 | 家长、老师各一件小事 |
| 激励 | 一个普通时刻 + 3-4 件今天能做的小事 | 允许一句一段 | 一句朴素的话 + 今天能答的问题 |
| 科技 | 一个场景 + 一个比喻 + 三个信号 | 混合 | 一句判断 + 真实体验 |

> 这六行是「每条赛道像它自己」的实际口径。改任何一行都要同时改
> `sys:{赛道}` / `s:{赛道}` / `v:{赛道}:*` 三处，否则会互相打架——
> 骨架卡的优先级最高（「与上文冲突时以本条为准」）。

`SYSTEM_PROMPT` 导出仍保留 = `sys:default` 模板 + 默认锚的渲染结果，供测试与排障引用。

## 4. 变体轮换

```
pickVariants(track)
  ├─ nextVariantCursor(track)       Setting.style_variant_cursor[track] += 1
  ├─ loadVariantLines(track, dim)   v:{赛道}:{dim} → 回落 v:global:{dim} → 回落代码默认
  └─ arr[cursor % arr.length]       三个维度各自取模
```

- 轮换周期 = 三个维度长度的最小公倍数
- 游标存在 `Setting` 表的 JSON 里（`{ "星座": 6, ... }`），只保留近 200 条赛道，防膨胀

### 分隔符规则（`splitVariantBlocks`，前后端同源）

```ts
// 有 --- 时：按块切，一块 = 一个变体（骨架卡）
text.split(/\n[ \t]*---[ \t]*\n/)
// 没有 --- 时：退回历史口径「一行一条」
text.split('\n')
```

- 前端 `web/src/utils/variants.ts` 与后端 `style-prompts.ts` **逐字同源**，
  否则会出现「页面显示 5 张、写稿按 34 条轮换」这种沉默的错
- 回写时不管哪种形态都统一用 `---` 拼接（多于一条），保证「点开看一眼再保存」不改格式

## 5. 确定性后处理（`postProcess`）

```
sanitizeModelHtml → processEmphasis → reflowParagraphs
```

| 步骤 | 文件 | 只改什么 | 绝不能改 |
|---|---|---|---|
| 清洗 | `html-sanitize.ts` | 去 markdown 围栏、清 `**` 加粗残留、补 `<p>`、救回被写成 `<strong>` 的标题 | 正文措辞 |
| 强调 | `emphasis.ts` | 补加粗到 8-12 处、红字 2-3 处 | 句意、段落划分 |
| 段落重排 | `paragraph-reflow.ts` | 按段长阶梯切分超长段落 | 句子顺序、字数 |

顺序不能变：强调在前（重排按 `<strong>` 是原子单元切句），省略号/标点在最后。
新稿与修补稿**都走这条链**（修补是让模型复述整篇，会顺手改坏红字与分段）。

> 注：`ellipsis.ts`（省略号补齐）已从链路摘除，文件保留；它只服务于已下线的去 AI 味条款。

## 6. 体检与修补

### 6.1 门禁分级（`lint.ts`）

**error（拦推送）**

| code | 判据 |
|---|---|
| `sections` | 小标题 3-4 个 |
| `chars` | 正文 1300-2300 字 |
| `dash` | 破折号 0 处 |
| `negation` | 否定框架 0 处（不是X而是Y / X而非Y / 少X多Y / 与其X不如Y…） |

**warn（只提示，不拦）**

| code | 判据 |
|---|---|
| `para_shape` / `para_short` / `para_overlong` | 复合长段落占比、一句一段占比、单段 >150 字 |
| `summary_openers` | 小标题下先写总结判断 |
| `ending_hook` | 结尾没有第二人称提问 / 没有回扣物件 |
| `emphasis` / `key_emphasis` | 加粗 8-12 处、红字 2-3 处 |
| `citation` | 无出处的权威引用（研究表明 / 专家发现…） |
| `fear_selling` | 恐吓 / 贩卖焦虑句式 |
| `zodiac_topic` / `zodiac_textbook` / `zodiac_repeat` | **赛道专项**，由 `r:{赛道}.checks` 决定是否启用 |
| `zodiac_dup` | 同一个星座被写进多个段落（群像是「一星座一段」）。**2026-11-12 真机实测必须加这条**：模型会老实列完 10 个星座，又给其中 5 个补 2-3 段小故事，段落数 14→21，形态从群像退回散文，而其它检查全绿 |

> **赛道豁免**：`r:{赛道}.relax` 可列出要跳过的 **warn** code。
> 星座群像（一星座一段）与育儿口语体（一句一段）按散文标准必然触发
> `para_shape` / `para_short`，那是**形式不同**而不是写坏了，用散文尺子量清单体只会刷假警报。
> **只允许豁免 warn**：error 是合规门禁，任何赛道都不能关（`lintArticle` 里强制）。

> `ai_taste` 已整体移除（2026-11-11），见第 8 节。

### 6.2 修补循环（`generateDraft` 内）

```
lintArticle → 有 error 就 repairOnce(带上命中片段) → 重新体检
           → 最多 2 轮，distance() 没变小就停
```

`distance() = error 数 × 10000 + 字数偏离量`。带偏离量是因为：2858 字改到 2789 字，
error 数没变（仍是「超字数」1 项），但确实更接近合格线，这一轮该算进步。

修不动的稿子留在草稿箱让人工处理，并在 `note` 里说清剩什么问题——比无限重试划算。

## 7. 选题层（`angles.ts`）

- **扩库**：`expandAnglesForTrack()` 注入创作总纲 + 本赛道选题形态，让模型出角度
- **守门**：`topicRejectReason(c, trackName)`
  - 通用：tail 必须带「方法钩子」（怎么 / 如何 / 怎么办…），否则拒（防止选题停在纯困境）
  - `angleMode='zodiac'`：反过来**禁止**问题咨询式，必须挂星座锚、有具体画面
- 扩库与写稿**共用同一份创作总纲**（正能量：不放大痛苦、不制造焦虑）

## 9. 前端：文风配置页（`web/src/views/StylePromptsView.vue`）

- 左侧：`创作总纲` + 各赛道（**只列真赛道**；`s:` / `r:` / `v:` 这类机器 key 按前缀过滤掉）
- 右侧：赛道下分 6 个 Tab
  - **系统提示词**（`sys:{赛道}`，`## system` + `## tail`，页内列出可用变量）
  - 赛道文体（`{赛道}`）
  - **写作规范**（`s:{赛道}`，按 `##` 分节）
  - 标题变体 / 结构变体 / 篇幅变体（`v:{赛道}:*`）
- 变体编辑器（`components/VariantLinesEditor.vue`）：
  - **结构变体 = 卡片式**：卡头显示「骨架名」，正文多行输入框，`---` 不出现在界面上
  - 标题 / 篇幅 = 单行条目；篇幅做格式校验并标红
  - 顺序即轮换顺序，可上移 / 下移 / 删除
- 页头显示「本赛道自己的库 · 共 N 张 · 下一篇用第 K 张」，来源可能是「本赛道 / 回落全局 / 内置兜底」

## 11. 改东西之前必须知道的 6 条

1. **数值锚不进可编辑文本**。3-4 小标题 / 1300-2300 字 / 17-19 段 / 破折号与否定框架禁令，
   全部由 `constants.ts` 生成。可编辑 ≠ 可改门禁——页面上把某赛道写成「5 个小标题」，
   而 lint 仍按 3-4 拦，就是自己打自己（历史上踩过）。
2. **前后端切分口径必须同源**。改 `splitVariantBlocks` 一定要同步 `web/src/utils/variants.ts`。
3. **代码里不许出现赛道名**。要差异化就写进 `r:{赛道}` / `s:{赛道}` / `v:{赛道}:*`，
   新增一条赛道应该是**零代码改动**。
4. **预算按块丢弃，不切尾巴**。见 3.2，半截指令比没有更糟。
5. **tail 不可截断**。选题、变体、篇幅锚、结尾钩子都在 tail 里，它们进不去等于这篇文章白写。
6. **提示词与门禁要同源**。改了 prompt 里的字数/节数，必须同时改 `constants.ts`，
   否则模型被要求 A、门禁按 B 判。
7. **提示词只许存在配置表里，不许回到代码**。`sys:{赛道}` 是唯一来源；
   往 `writer.ts` 里再写一段文体规则，等于又开了一条「六条赛道共用」的暗渠。
   要新增赛道差异化，改 `sys:` / `s:` / `v:` / `r:` 四张表，不改代码。

## 12. 已知取舍与遗留

| 项 | 状态 |
|---|---|
| 去 AI 味 | 整体下线，只留接口。当前**没有任何 AI 味检测** |
| 半步科普句 | 星座 `sys:` 已明令禁止解释腔（「在社会化进程中」「往往源自」），但 lint 只能查教科书外观的引用，查不出这类措辞 |
| 星座专项体检 | 只 warn。`r:星座` 默认启用 `zodiac_topic / zodiac_textbook / zodiac_repeat` |
| 骨架卡质量 | 2026-11-12 按形态重写过一轮（星座 4 张群像 + 1 张单星座、育儿 4 张），**尚未经过多篇真实数据检验** |
| 段落重排 | 阶梯跨节连续（修过一个「每节节奏一模一样」的 bug），但仍是确定性算法，风格固定 |
| 标题 | 仍只靠 `v:{赛道}:title` 轮换。实测六条赛道会收敛到同一句式（「那个…的深夜，我在…里听见了回声」），根因是句式模板本身趋同，尚未处理 |
| 真实样本比对 | 没有「与近 N 篇比对差异度」的机制，也没有真实爆款样本库（`docs/TRACK-FORM-RESEARCH.md` 的阶段 3） |
| **群像的分段失控** | 真机实测（2026-11-12，n=3）：星座稿能点名 7-10 个星座、标题也像星座文了，但模型会把每个星座**拆成 2-3 个 `<p>`**，段落数 14→21，`zodiac_dup` 报 warn。提示词写「一段」管不住 `<p>` 的切分。**下一步**：在 `postProcess` 里做确定性合并（相邻且只提同一个星座的段落合并），而不是继续加提示词 |
| **清单体的序号分段** | 职场稿的 5-7 条自测项，模型会把 2-3 条塞进同一个 `<p>`。已加 `zodiac_dup` 那套思路的姊妹问题。**下一步**：`postProcess` 的「序号分段器」（把含 `N. ` 的段落按序号切开） |
| **提示词自伤** | 提示词里的示范句会教坏模型：旧开头写「他们要的是 X，不是 Y」，稿子里就稳定出现「不是…而是…」（error 级，拦推送）。改示范、不改禁令——迁移 v9 已处理。**新增赛道文案时先自查：有没有在示范你禁止的句式** |

## 13. 怎么验证

```bash
cd server
npm run typecheck          # 类型
npm run smoke:lint         # 体检 + 提示词注入 + 赛道模板隔离 + 后处理（116 项）
npm run smoke:style        # 配置读写 / 变体切分 / 轮换（33 项）

```

`verify:zodiac` 会在 `var/verify/` 下留 HTML 现场，断言的是**确定性项**
（星象词数量、教科书腔、跨星座复读、推送门禁），随机量（字数、段数）只报中位数。

> ⚠️ 铁律：任何写库的验证脚本，先复制 `dev.db` 到临时库再跑。`verify:zodiac` 是样板。

## 14. 下次优化的切入点（建议）

按影响面排序：

1. **新形态的真机效果**——`sys:` 已按赛道分开，但只有提示词层面的验证（116 项断言全过）。
   需要星座 / 育儿各生成 5 篇，人工比对「像不像那个赛道的爆款」。这是唯一验收标准。
2. **标题句式趋同**——六条赛道的标题最后仍收敛到「场景定语 + 人 + 其实」。
   标题公式库是「一行一条」，缺一个「句式结构」维度的轮换。
3. **去 AI 味重启**——接口已就位，需要定阈值真源与「warn 还是拦」
4. **选题与写稿的一致性**——选题由模型出、写稿由模型写，两者对「这条角度该怎么写」的理解可能不一致
5. **多篇之间的差异度**——现在只靠变体轮换，缺少「与近 N 篇比对」的机制
6. **创意招式库**（`docs/TRACK-FORM-RESEARCH.md` 档 2）——起外号 / 成人世界类比 / 角色互换
   现在只写在各赛道提示词里，还不能轮换与统计
