# 设计评审请求：公众号 AI 内容生产系统的「形态一致性」问题

> 这是一份**自洽**的技术说明，供第三方 AI 做架构评审。不依赖任何上下文。
> 请重点回答第 8 节的 5 个问题。

---

## 1. 系统是什么

一个公众号 AI 内容生产系统（Node22 + TS + Express + Prisma + Vue3）。目标是按「赛道」（星座 / 育儿 / 职场 / 教育 / 激励 / 科技）自动写公众号文章，推到微信草稿箱（群发永远人工）。

流水线：

```
选题扩库 → 排产 → 写稿 → 落库草稿 → 人工审 → 推草稿箱 → （人工群发）
```

写稿内部：

```
读配置 → 三维变体轮换 → 渲染 system 消息 → 拼 user 消息 → 调 LLM
  → 后处理（清洗/强调补齐/段落重排）→ 体检 lint → 定向修补（≤2 轮）→ 落库
```

---

## 2. 配置体系（7 类，全部落在一张 `StylePrompt` 表）

| key | 含义 | 格式 | 谁读 |
|---|---|---|---|
| `global` | 创作总纲（正能量/事实/逻辑） | 自由文本 | 写稿 + 扩库 |
| `{赛道}` | 赛道文风（语气/读者/禁忌） | 自由文本 | 写稿 |
| `sys:{赛道}` | **系统提示词**（形态/结构/禁令） | `## system` + `## tail` 两节，含 `{{变量}}` | 写稿 |
| `s:{赛道}` | 写作规范（段落形态/强调/句式禁忌） | `##` 分节 | 写稿 |
| `v:{赛道}:title/structure/length` | 变体库（标题公式/骨架卡/篇幅档） | 一行一条，`---` 分隔 | 写稿（轮换） |
| `r:{赛道}` | 机器规则（体检项/选题形态/豁免） | JSON | 体检 + 选题 |

`sys:` 里的数字用变量占位，渲染时注入：`{{minSections}} {{maxSections}} {{targetMin}} {{targetMax}} {{minChars}} {{maxChars}} {{pMin}} {{pMax}}`。

user 消息拼装顺序：`赛道名 → 总纲 → 赛道文风 → 写作规范三节（预算 7600 字，整块丢弃）→ 本次选题 → 本次变体（标题公式 + 骨架卡 + 篇幅档）→ sys 的 tail 节`。

**注意**：变体段里有一句「结构骨架按这条展开（**与上文结构规范冲突时以本条为准**）」——骨架卡优先级最高。

---

## 3. 门禁与体检

成稿体检 `lintArticle` 确定性执行（不依赖模型）：

- **error（拦推送）**：小标题 3-4 个 / 正文 1300-2300 字 / 无破折号（——）/ 无否定框架（「不是X而是Y」等）
- **warn（只提示）**：段落形态（复合长段占比、一句一段占比）/ 结尾钩子 / 加粗密度 / 无出处引用 / 焦虑贩卖 / 赛道专项（`zodiac_topic` `zodiac_textbook` `zodiac_repeat` `zodiac_dup`）
- 定向修补只修 error，≤2 轮，用一个 `distance()`（error 数 + 字数偏离）判进步，没进步就停

---

## 4. 问题与证据

核心症状：**同一条赛道，文章形态不达标**。以星座为例，它应该是「十二星座群像，每个星座一段」，实际产出大量同星座多段、段数膨胀、偶尔完全跑题。

量化工具：统计每篇的「星座数（覆盖几个）」「同座多段（同一星座出现在几个 `<p>`）」「段数」「字数」。

| 轮次 | 提示词改动 | 样本 | 覆盖星座数 | 同座多段（几个星座被写多段） |
|---|---|---|---|---|
| 基线 | 「禁止给同一个星座写两段」 | 1 | 8 | 5 |
| +「每个星座名只出现一次」 | | 3 | 9 / 2 / 11 | 0 / 0 / 3 |
| 删掉一张自相矛盾的骨架卡 | | 3 | 11 / 10 / 6 | 3 / 0 / 1 |
| 「恰好 10 个」 | | 4 | 9 / 10 / **0** / 8 | 9 / 4 / 0 / 8 |
| 「恰好 12 个」+ 小标题必须「类别+数量」 | | 4 | **12 / 12 / 12 / 11** | 3 / 2 / 11 / 2 |
| + 每段以「星座名：」开头 | | 4 | 11 / 12 / 11 / 12 | 10 / **12** / 5 / 10（更糟，已回退） |

**结论：**
- **覆盖率**（写几个星座）：提示词能搞定 → 12/12 命中
- **唯一性**（每个只写一段）：20 篇只有 2 篇干净，加提示词无效甚至更糟
- 段数 16-32 波动，字数 1038-2443 波动

其他证据：
1. **模型段均字数恒定在 69-75 字**（不管提示词要求 80-130）
2. **算术矛盾**：12 星座段 × 74 = 888 字 + 5 段场景 × 74 = 370 → **1258 字，够不到 1300 门禁**。模型于是加段补字数 → 重复就是这么被逼出来的
3. **否定框架**（`不是X而是Y`，error 级）在 11 篇里拦下 4 篇，定向修补修不动
4. **小标题措辞决定成败**：写「那三个 / 那几个」时正文会通篇不点名星座（一篇 0 个星座名）；写「火象三座：…」时覆盖率立刻稳
5. **配置冲突**：骨架卡里有一张「单星座深挖（一篇只写一个星座）」，与「十二座写满」直接冲突，抽到它时模型两边折中成「只写 2 个」
6. **选题与形态打架**：选题层生成的是单星座角度（「射手座因追求自由…」），写稿要十二座群像，模型只好围绕射手写一堆（射手×4）
7. **提示词落盘实测**（把每次发给模型的成品存下来）发现：去重要求**传了 7 处**，但同时传了互相打架的指令

---

## 5. 根因分析（当前判断）

1. **形态契约没有单一真源**。「一篇文章长什么样」散落在 4 处各写各的：选题 prompt、`sys:`、`s:`、骨架卡，而且骨架卡优先级最高，可以覆盖其它。
2. **分工错了**：模型同时负责「写什么」和「怎么分段、分几段、哪段归谁」。后者是结构问题，模型不可靠——局部计数（写几个）它数得清，全局归属（每个只写一段，跨 20 段）它管不住。
3. **约束靠"遵守"而不是靠"设计"**：提示词约束是软的，lint 是事后抓，修补是事后改。都是补丁，不是前置。
4. **改配置要配迁移**：默认文案写在代码里，库里是旧的，迁移靠手工盯版本号。今天一天跑了 v2→v15 共 14 次迁移，还实测出一次「改了代码、库里是旧的、静默不生效」。
5. **形态与门禁算术不匹配**（见 4.2），模型被逼着加段。

---

## 6. 硬约束（不可违反）

1. **代码里不许出现赛道名**。禁止 `if (track === '星座') { ... }` 这类分支。
2. **配置非空**：赛道配置缺项就不能保存、不能写稿；**不做默认兜底**。
3. **前置驱动**：约束写在生成之前（选题、提示词），不写在生成之后（修补、合并）。
4. **不打补丁**：不做「事后合并段落」「事后切分段落」这类确定性改写。
5. **数字不写死在自由文本**：节数/字数/段数必须可校验，不能让页面写「5 节」而门禁按 3-4 拦。
6. 体检的 error 是合规门禁（拦推送），warn 只提示；赛道可以豁免部分 warn。

---

## 7. 候选方案

**数据层（真源在哪）**

- **A 档**：不引入新结构。形态仍写在 4 段自由文本里，靠约定 + 正则比对数字做启发式校验 + 选题守门。
- **B 档**：引入结构化对象 `form`（必填 JSON），是形态唯一真源，选题/写稿/骨架卡/体检四方从它派生，保存时做**算术校验**（如 12 个 × 1 段 + 5 段 = 17 ✓）。

**过程层（结构由谁保证）**

- **C 结构先行**：程序按 `form` 生成 HTML 骨架（带槽位），模型只填空。形态 100% 达成，但怕模板化。
- **D 计划先行**：先让模型只出「计划」（12 个星座名 + 每个的切片方向 + 分组小标题），程序校验计划（个数、不重复、格式），再让它照计划写正文。全局约束在计划阶段解决（那里是清单，好验证）。
- **F 标记切分**：模型用分隔符写主体，程序按标记切段。

**当前倾向**：B（数据）+ D（过程）。B 是地基（数字有真源、可校验），D 改分工（结构在生成前由程序把关）。

---

## 8. 想请第三方回答的 5 个问题

1. **B + D 是不是过度设计？** 有没有更简单的方案能解决「唯一性」这个全局约束？（比如：根本问题是不是出在别处？）
2. **「12 个主体各一段」与「1300 字下限」的算术矛盾怎么解？** 模型段均 74 字是实测恒定的。放宽场景段数、降低字数下限、还是换形态？哪个更合理？
3. **全局约束（每个主体只出现一次、跨 20 段）** 除了「计划先行」，还有没有更可靠的做法？提示词已证明无效。
4. **配置 7 类是否太多？** 怎么收敛才既保持「赛道像它自己」，又不至于改一处要改四处？`sys:` / `s:` / 骨架卡 三者职责怎么切才不打架？
5. **否定框架（`不是X而是Y`）** 是 error 级禁令，但模型稳定产出、定向修补也修不动。这类**文体禁令**的可靠执行方式是什么？（现状：提示词禁 + lint 抓 + 修补改，三道都失灵）

## 附：模型与运行环境

- 模型：Agnes 3.0 Flash（OpenAI 兼容协议 `chat/completions`）
- 已探测：支持 function calling（传 `tools` 会返回 `tool_calls`）；**不支持厂商内置联网**（`tools:[{type:"web_search"}]` 返回 400）；不带工具时模型自述无联网能力
- 每篇生成走完整链路（含 ≤2 轮定向修补），单篇 40-90 秒
- 体检与后处理都是确定性代码，不依赖模型
