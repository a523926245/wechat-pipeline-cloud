# 赛道形态调研（Phase 1：诊断 + 爆款拆解 + 改造方案）

> 状态：2026-11-12。本文是「结构同质化 / 文风不适配赛道」这一问题的**基线文档**。
> 上游：`docs/WRITING-PIPELINE.md`（工程链路）。
>
> **落地进度**：档 1（形态档案）已实施，形态不在代码里、不在 `f:`，而是整份
> `sys:{赛道}` 系统提示词入库（见第 9 节）。档 2（创意招式库）与档 3（样本库）未做。

## 0. 结论先行

问题不在提示词写得不够细，在**架构少了一层**：

> 现在系统能配置「**文风**」（怎么说话），不能配置「**形态**」（文章长什么样）。

六条赛道共用同一份 12 条系统提示词（`writer.ts: buildSystemPrompt`），
而那份提示词本身就是一个**完整的文体规格**：3-4 节、17-19 个复合长段落、
禁止一句一段、结尾回扣物件 + 第二人称提问。

于是无论赛道文风怎么写，产出的都是同一种东西：**深夜独白体情感散文**。
换赛道只是换形容词，换不掉骨架。

## 1. 证据：两篇样本剥掉内容后长得一模一样

### 1.1 标题同构

```
星座：【话】那个把辞职信摔在桌上的白羊座，其实只是不想再装大人了
育儿：【话】挤地铁时被孩子喊"抱"的深夜，我在那句"等我回去"里听见了回声
        └─ 场景定语 ─┘        └ 人/我 ┘  └ 其实/在…里 ┘ └ 抒情落点 ┘
```

两条赛道的标题公式库完全不是一套（星座有「天象挂载/反刻板/对号入座」，
育儿有「场景痛点/数字清单/成长时刻」），产出却是**同一个模板**。
原因在第 2 条系统提示词：「带画面感或情绪钩子，不用干巴巴的标签词」——
这一条把六条赛道统一成了抒情散文标题。

对比真爆款的标题：「十句话形容你认识的XX座」「越没本事的父母，越喜欢逢人就晒这 2 件事」。
**它们不是同一类标题**：一个是"我要写一篇美文"，一个是"我要让你立刻想点开/转发"。

### 1.2 骨架同构

| 位置 | 星座样本 | 育儿样本 | 对应提示词 |
|---|---|---|---|
| 开篇 | 会议室、工牌、墨粉味 | 地铁十号线、八点十四分 | 第 3 条：具体时刻 + 感官细节 |
| 02 | 外人眼里就是个玻璃心 | 我把「抱抱」听成了指责 | 第 4 条：禁总分总，直接写场景 |
| 03 | 真相：我怕父母失望 | 换做法：非暴力沟通 | 方法位 |
| 04 | 回扣工牌 / 门禁卡 | 回扣旧胸针 | 第 9 条：回扣物件 + 第二人称提问 |
| 结尾句 | 「你手机里那条…还亮着吗？」 | 「那枚旧胸针还在你的包上吗？」 | `TRACK_FLAVOR.ending` |

**两处硬证据：**

1. **示范句被逐字抄袭**。星座样本结尾前半句「你手机里那条到现在还没回的消息，还亮着吗？」
   与 `writer.ts` 里 `TRACK_FLAVOR.星座.ending` **一字不差**。示范句被当成了模板。
2. **教科书腔是"每段一次推进"逼出来的**。星座样本第 37 段：
   「白羊座在社会化进程中，常常被赋予"强者"或"开拓者"的角色期待」——
   这句在星座赛道是明令禁止的（`s:星座` 禁忌：不塞心理学概念）。
   但系统提示词要求每段「一段之内至少完成一次推进（发生了什么 → 我怎么想 → 我说了什么）」，
   模型只能给每个场景配一句解释收束。**要求写解释，就不可能不出现解释腔。**

### 1.3 段落节奏同构

两篇都是复合长段落（3-5 句 / 60-140 字）、第一人称心理旁白、段均 100+ 字。

而调研到的真爆款：**星座是短切片，育儿是一句一段**。我们两条赛道的核心节奏，
恰好都被同一条门禁（`MAX_SHORT_PARA_RATIO = 1/2`、`MIN_LONG_PARA_RATIO = 1/3`）掐死了。

## 2. 真爆款长什么样（调研）

### 2.1 星座：形态是「群像速写」，不是「一个人的故事」

以同道大叔为原型的头部星座号，稳定 10 万+ 的做法：

| 维度 | 做法 |
|---|---|
| 覆盖 | **一次 7-12 个星座**，每个 1-3 句，不是只写 1-2 个 |
| 单位 | 一个**行为切片**（「生气时不说话，回房间把门关得很轻」），不是一段完整故事 |
| 标题 | 「十句话形容你认识的XX座」「如何逼疯/追求/甩掉XX座」「12星座最讨厌的…」 |
| 价值 | **认同感**（"这说的不就是我吗"）+ **社交货币**（"发给他看"） |
| 禁忌 | 不解释心理机制、不写长场景、不做科普 |

**最致命的一条**：星座内容的商业模式是「覆盖所有人」——
读者要在文里找到自己那个星座。我们写成一个完整故事，只点名 1-2 个星座，
**12 个读者里有 10 个看不到自己**，认同感和转发理由同时消失。

现有配置甚至主动限制：「分星座写时只写 7-9 个，不许写满 12 个」（合理，防模板），
但在 17-19 段 × 60-140 字的门禁下，7-9 个星座根本塞不进去，
模型只能退回「1 个星座 + 1 个故事」。

### 2.2 育儿：形态是「反常识断言 + 四拍清单」

以「贼娃」类账号（篇篇 3-5 万）拆解出的套路：

| 维度 | 做法 |
|---|---|
| 标题 | 反常识断言 + 数字 + 戳痛点：「越没本事的父母，越喜欢逢人就晒这 2 件事」 |
| 结构 | 总分总清单体，`01/02/03` 数字小标题（2-5 字） |
| 每个分点 | **固定四拍**：现象白描 → 心理学解释 → **成人世界类比** → 给建议/给安慰 |
| 创意引擎 | **给行为起外号**：带怪东西回家=「打猎」、退行=「缩小」、睡前唠叨=「废话搭子」 |
| 语言 | 短句、短段、**大量一句一段**、口语（咋了/妥妥/你就完了） |
| 转发理由 | **角色互换类比** → "我要发给我老公看" |

对照我们的育儿样本：只有一个场景 + 一个方法，
- 没有外号（「抱抱」没被命名）
- 没有成人世界类比（这是最强共情招，一个都没有）
- 没有一句可摘出来单独转发的话
- 引用了《非暴力沟通》，但它是**贴上去的背书**，不是从场景里长出来的

而且我们的「禁止一句一段」与这个赛道的核心节奏**正面冲突**。

### 2.3 跨赛道的四条共同规律

1. **标题先于内容成立**——标题本身就是内容，不是内容的摘要。
2. **开头 3 秒给"这说的是我"**，不给氛围。
3. **形式感就是分享理由**：编号、清单、外号、对照表——读者转的是"这个形式"，不只是观点。
4. **结尾是转发指令，不是思考邀请**。我们现在的「回扣物件 + 问读者」在散文里对，
   在爆款里弱——它只要求读者"想一想"，没要求"转出去"。

## 3. 根因定位（代码级）

| 文件 | 位置 | 问题 |
|---|---|---|
| `server/src/services/writer.ts` | `buildSystemPrompt` 12 条 | 全局唯一文体规格，与赛道无关 |
| `server/src/constants.ts` | `MIN/MAX_SECTIONS` 3-4 | 全局，无赛道维度 |
| 〃 | `PARA_TARGET_MIN/MAX` 17-19 | 全局，锁死"长文叙事" |
| 〃 | `MIN_LONG_PARA_RATIO` 1/3、`MAX_SHORT_PARA_RATIO` 1/2 | 全局，锁死"复合长段落" |
| `server/src/services/lint.ts` | 442-462 | 段落形态判据读全局常量 |
| `server/src/services/style-prompts.ts` | `DEFAULT_TRACK_PROMPTS` | 只有「调性/读者/语气/禁忌」= **形容词层** |
| 〃 | `DEFAULT_VARIANT_LINES.*.structure` | 6 赛道 × 4-5 张卡，**共享同一元结构**：场景 → 展开 → 收束 → 回扣提问 |
| `server/src/services/writer.ts` | `TRACK_FLAVOR.ending` | 示范句被模型逐字复制 |

**一句话**：`v:{赛道}:structure` 只改"分几节、每节干什么"，
改不了"这是一篇清单文还是一篇散文"。缺的那一层叫**形态（form）**。

> 注意 `constants.ts` 顶部的铁律：「数值锚不进可编辑文本」。这条不能破。
> 所以形态配置必须走**结构化 JSON + 校验**（类似 `r:{赛道}`），不能写成自由散文。

## 4. 改造方案

### 档 1：形态档案 `f:{赛道}`（推荐，必做）

新增一份受校验的结构化配置，决定"这篇长什么样"：

```jsonc
{
  "sections": [3, 4],          // 节数
  "paras": [10, 13],           // 段数锚
  "chars": [1600, 2000],       // 字数（须落在门禁 1300-2300 内）
  "rhythm": "short",           // long | mixed | short  → 决定段落形态判据
  "allowList": true,           // 是否允许短句清单
  "h2Style": "group",          // scene | number | group | topic
  "ending": "cta",             // question | slogan | cta | none
  "minEntities": 7,            // 至少点名多少个星座/对象（覆盖度要求）
  "forbid": ["textbook"]       // 该形态额外禁项
}
```

落地要点：
- `buildSystemPrompt` 的第 2/3/5/7/9 条改成**读 form 参数**，不再是硬编码
- `lint.ts` 的段落形态判据改为**按 form.rhythm 取值**（同一套规则，阈值来自赛道）
- `f:` 是 JSON、有 schema 校验、有默认值兜底——满足"可配置 ≠ 可改门禁"的原则
- 新增赛道仍可零代码改动（沿用 `r:{赛道}` 的既有范式）

### 档 2：创意招式库 `m:{赛道}`（推荐，第二期）

现在的"创意"全押在骨架卡上，但骨架卡是**节结构**，不是创意。
真正的创意是可枚举的**招式**：

| 招式 | 适用 | 例子 |
|---|---|---|
| 起外号 | 育儿/职场 | 「带怪东西回家」→ 打猎 |
| 成人世界类比 | 育儿 | 晒孩子成绩 = 你妈逢人讲你月薪 |
| 角色互换 | 育儿/星座 | 「换成你被这样问，你什么感觉」 |
| 一句话鉴定 | 星座 | 「XX 座：嘴上说随便，心里已经排好了顺序」 |
| 反常识断言 | 全赛道 | 「越…越…」 |
| 数字清单 | 全赛道 | 「5 个信号」 |

每篇轮换 1-2 个招式注入 tail，和现有三维变体同一套游标机制。
**这是"创意"第一次变成可配置、可轮换、可验证的东西。**

### 档 3：赛道样本库（少样本学习，暂不做）

存真实爆款片段作 few-shot。风险：7600 预算、版权、抄袭判定。等档 1+2 跑稳再说。

## 5. 两条赛道的形态草案

### 星座

| 形态 | 结构 | 段落 | 结尾 |
|---|---|---|---|
| **A 群像速写**（主推） | 开篇 1 段场景 → 7-9 个星座各 1 段 40-70 字 → 收尾 1 段 | 10-13 段，短段为主 | 「你是第几个」/「@ 那个 XX 座」 |
| B 对号入座清单 | 12 条行为，每条一句，前 3 条加粗 | 14-16 段 | 转发指令 |
| C 单星座深挖 | 保留现有叙事骨架 | 17-19 段 | 保留提问 |

> C 是现有唯一"对"的形态——星座长文确实可以这么写。问题是它不该是**唯一**形态。

### 育儿

| 形态 | 结构 | 段落 | 结尾 |
|---|---|---|---|
| **A 反常识 + 四拍清单**（主推） | 1 个反常识断言 → 3 个分点，每点四拍 | 短段/一句一段为主 | 一句可摘的狠话 + 转发指令 |
| B 外号命名型 | 给 3-4 个行为起外号，每个外号一节 | 中短段混排 | 提问 |
| C 一个瞬间复盘 | 保留现有 | 复合长段 | 保留回扣物件 |

## 6. 建议落地顺序

1. **先把形态层做出来**（`f:{赛道}` + system prompt 参数化 + lint 按形态判），不动任何文案
2. 星座先跑 A「群像速写」、育儿先跑 A「四拍清单」，各真机生成 5 篇
3. 人工比对：像不像那个赛道的爆款（这是唯一验收标准，不能只看 lint 过没过）
4. 稳定后再上招式库 `m:{赛道}`
5. 最后处理「结尾形态」与「标题公式」的赛道化（标题现在是第 2 条提示词统一掉的）

## 7. 原待拍板项（2026-11-12 已定）

用户的答复是原则性的：**「每个赛道写出来的文章要像它自己，不要被统一管住；
提示词放文风配置里，不硬编码」**。据此四个问题都按「允许」处理：

1. 星座允许「7-9 个星座、每个 1 段」——篇幅档改为 11-14 段，不再是 17-19
2. 育儿允许「一句一段为主」——`r:育儿.relax` 豁免 `para_short`
3. 结尾允许「@某人 / 截图句」代替「回扣物件 + 提问」——写在各赛道 `## system` 里
4. 星座字数不再放宽到 1200，仍守 1300 门禁；档位靠段数与每段字数控制

原文保留如下，供回看当时的推理：

1. **星座是否允许「7-9 个星座、每个 1 段」**——会打破现有 17-19 段 / 每段 60-140 字
2. **育儿是否允许「一句一段为主」**——会打破 `MAX_SHORT_PARA_RATIO = 1/2`
3. **结尾是否允许「@某人 / 转发指令」代替「回扣物件 + 提问」**
4. **星座速写字数是否放宽到 1200**（门禁下限 1300 要不要按形态分档）

> 这四条都是"要不要让门禁按赛道分档"的同一件事。落地方式见第 9 节。

## 9. 已落地：档 1 改成了「整份提示词入库」（2026-11-12）

### 9.1 为什么不是 `f:{赛道}` 形态档案

原方案是新增一个结构化 JSON 管形态参数。实施时改了主意，因为用户的诉求是
**「文风配置里可以配置提示词，不要硬编码到代码里」**——参数化的 JSON 仍然是代码在描述形态，
只是换了个说法。改成整份提示词入库后：

- 赛道形态的每一句话都可在页面上改，不需要为了「星座要不要一句一段」改代码；
- 新增赛道仍然零代码改动（`sys:default` 兜底）；
- 数字锚没有失守：节数/字数/段数只能用 `{{变量}}`，且模板漏写时程序补硬锚。

代价：形态是自然语言，程序无法校验「它到底是不是清单体」。所以体检侧只做
「按赛道豁免 warn」（`r:{赛道}.relax`），不做形态识别。这是有意的取舍。

### 9.2 分层（四层，各有各的职责）

| 层 | key | 管什么 | 例 |
|---|---|---|---|
| 形态 | `sys:{赛道}` | 这是一篇什么文（群像 / 清单 / 三方视角） | 「正文必须点名 7-9 个不同星座」 |
| 语气 | `{赛道}` | 用什么口吻说话 | 「轻松俏皮 + 有梗，毒舌但不刻薄」 |
| 本篇骨架 | `v:{赛道}:structure` | 这一篇分几节、每节干什么 | 「第二节：火象三座各一段」 |
| 段落纪律 | `s:{赛道}` | 段长、强调、额外禁忌 | 「一星座一段，2-4 句」 |

**排查同质化时必须四层一起看。** 本轮先后发现三层硬编码：
system（12 条共用）、结构偏好行（六条赛道是同一句流水线）、骨架卡（全是
「场景开场 / 误判 / 转折 / 回扣物件提问」）。只改一层，另两层会把稿子拉回原形——
骨架卡的优先级甚至是「与上文结构规范冲突时以本条为准」。

### 9.3 各赛道的形态落点

| 赛道 | 形态 | 段落节奏 | 结尾 |
|---|---|---|---|
| 星座 | 群像切片，7-9 个星座各一段 | 短段 30-70 字是常态 | 截图句 /「你是第几个」 |
| 育儿 | 反常识 + 四拍清单（白描→解释→成人世界类比→给动作） | 允许一句一段 | 可转发到家庭群的一句话 |
| 职场 | 冲突现场 + 一条判断标准 + 2-3 个动作 | 混合 | 处境的提问 |
| 教育 | 三方视角 + 事实线 | 混合，允许列表与对照 | 双方各一件小事 |
| 激励 | 小事清单（1 个方法 + 失效边界） | 允许一句一段 | 回扣开场的提问 |
| 科技 | 一个场景 + 一个比喻 + 边界 | 混合 | 判断 + 真实体验 |

### 9.4 存量库迁移

老库里已有 `s:` / `v:` 行，改代码种子不会生效。加了三个版本标记
（`style_seed_v2/v3/v4`），只升级「逐字仍是旧种子」的行：段落形态块、
六条赛道的结构偏好行、星座/育儿的骨架卡与标题库、两条赛道的篇幅档。
人改过的配置一律不动——这也是为什么迁移用「首行签名 + 全文比对」而不是无条件覆盖。

### 9.5 还没做

- **档 2 创意招式库**：起外号 / 成人世界类比 / 角色互换现在只写在各赛道提示词里，
  不能轮换、不能统计用了几个。
- **档 3 真实样本库**：没有 few-shot，模型对「这个赛道的爆款长什么样」只能靠文字描述想象。
- **形态识别**：lint 认不出一篇文章「是不是清单体」，只能靠豁免 warn 来止损。

### 9.6 验收

```
server: npm run typecheck ✓ / smoke:lint 116 项 ✓ / smoke:style 33 项 ✓
web:    npm run typecheck ✓ / npm run build ✓
真机:   verify:zodiac ✓ 28 项断言（隔离库，n=1，跑了 3 轮）
```

**真机三轮的演进（同一选题「水逆第三天 / 已读不回」）**

| 轮次 | 标题 | 字数 | 段数 | 结果 |
|---|---|---|---|---|
| v1 | 水逆第三天，8 个星座把「已读不回」演成了行为艺术 | 1154 | 15 | 门禁拦下（低于 1300） |
| v2 | 10 个星座在水逆第三天的已读不回，第 5 个最会装忙 | 1442 | 18 | 门禁过，但同一星座被写了两段 |
| v3 | 水逆第三天：7 个星座把「已读不回」说成「手没电了」 | 1527 | 21 | 门禁过，`zodiac_dup` 报 warn |

**已经确认有效**：标题从「那个把辞职信摔在桌上的白羊座，其实只是不想再装大人了」变成
「7 个星座把「已读不回」说成「手没电了」」——数字 + 星座 + 具体行为，是品类该有的标题；
小标题从叙事变成分组（「火象：消息发出去像丢进黑洞」）；正文能点名 7-10 个星座；
星象词 12-18 个（基线 2）。

**还没解决**：模型会把每个星座拆成 2-3 个 `<p>`，段落数从 14 涨到 21，形态从群像退化成小故事。
提示词写「每个星座一段」管不住 `<p>` 的切分——**这是分段问题，不是措辞问题**。
下一步做 `postProcess` 的确定性合并（相邻且只提同一个星座的段落合并），而不是继续加提示词。

**v1 的教训**：第一版把「每座 30-70 字」写死，15 段也凑不到 1300 门禁，稿子直接被拦。
**给形态定字数时必须先算一遍能不能落进门禁区间**，否则模型越听话越通不过。

## 10. 另外四条赛道：调研与落地（2026-11-12 下午）

星座与育儿是第一轮，剩下四条（职场 / 教育 / 激励 / 科技）在本节。

### 10.1 调研结论

**职场**

| 维度 | 头部写法 |
|---|---|
| 标题 | 数字 + 痛点 + 结果（「占 3 条以上，说明领导已经非常讨厌你了」）／反常识颠覆／冲突 + 问句／扎心判断 |
| 结构 | 钩子 → 3-5 个小节，每节 = 一个观点 + 一个真实案例 + 一句金句 → 行动 |
| 杀手锏 | **自测清单**：读者边读边数「我占了几条」，这是职场文最容易被转发的部分 |
| 反例 | 抽象论述、鸡汤、排比口号 |

**教育**

| 维度 | 头部写法 |
|---|---|
| 转发逻辑 | 家长转的是**社交货币**：炫耀（我是懂教育的父母）／恐惧／站队，不是「内容质量」 |
| 政策解读 | 不复述原文，提炼「**家长最关心的家门口变化**」，用模拟家长提问组织（「三步搞懂登记入学」） |
| 可信度 | 具体场景替代数据罗列（碎纸机销毁简历、预约刷证入校）；权威来自细节颗粒度（书单带 ISBN） |
| 安全公式 | 现象描述 + 个体解决方案（比直接讨论政策安全得多，同样满足信息饥渴） |

**激励**

| 维度 | 头部写法 |
|---|---|
| 标题 | 年龄自嘲（「42 岁，我从零学 AI」）／后悔（「我后悔没早点知道」）／低门槛（「普通人如何…只靠…」）／做减法（「我把…戒了」）／别再（「别再…了」） |
| 结构 | 一个普通时刻 → 一条具体发现 → 3-4 件今天能做的小事 → 一句能截图的话 |
| 情绪 | 先共情、再给希望；**「戳穿伪好人」那一层我们不用**（与创作总纲的「不制造焦虑」冲突） |

**科技**

| 维度 | 头部写法 |
|---|---|
| 标题 | 数字 + 结果／对比反差／反常识／白话解释 |
| 结构 | 钩子 → 三个信号 → 深度解构 → 普通人怎么办 → 升华 |
| 口径 | **轻深度**：读者要「轻思考 + 重收获」，不要哲学课；「人类文明的分水岭」这类大词反而降低阅读 |
| 科普 | 一个生活比喻讲原理（「互联网上的交通规则」），术语必须配大白话 |

### 10.2 原配置的共同病灶

四条赛道的骨架卡是同一套节拍，只换了名词：

```
第一节：一个场景  →  第二节：两种做法/多方视角  →  第三节：一条标准/一句话  →  第四节：回扣物件 + 提问
```

这正是星座稿和育儿稿当初的病，只不过这次发生在另外四条赛道上。

### 10.3 落地后的形态

| 赛道 | 形态 | 段落节奏 | 结尾 |
|---|---|---|---|
| 职场 | 冲突现场 + 一条判断 + **5-7 条「占了几条」自测** | 混合（长场景 + 短判断） | 一句截图话 +「你占了几条」 |
| 教育 | 引一句原话 + 替家长提问 + **三步搞懂**（改了什么→对我家意味着什么→现在做什么） | 混合 | 家长、老师各一件小事 |
| 激励 | 一个普通时刻 + 一条发现 + **3-4 件今天能做的小事** | 允许一句一段 | 一句朴素的话 + 今天能答的问题 |
| 科技 | 一个场景 + **一个比喻** + 三个信号 + 两件能做的事 | 混合 | 一句判断 + 真实体验 |

### 10.4 真机结果（各 1 篇）

| 赛道 | 标题 | 字数/段数 | 门禁 |
|---|---|---|---|
| 职场 | 领导甩锅给你时，沉默是最昂贵的买单 | 1535 / 20 | 过 |
| 教育 | 老师一句「先适应两周」，你家孩子的同桌成了孤岛？ | 1801 / 22 | 否：3 处否定框架 |

小标题也变成了该有的样子：职场是「会议室里的沉默，把责任钉在了你身上 / 判断标准与自测 / 当自测项占满，如何收回责任」。

### 10.5 两个必须记住的问题

**① 提示词自己示范了禁令里的句式。**
六条赛道的旧开头写着「他们要的是 X，**不是** Y」——而同一份提示词第 9 条写着
「禁止否定框架（不是X而是Y）」。模型模仿的是**范例的句式**，不是禁令的字面，
于是稿子里稳定出现「沉默被解读为认领，而不是思考」「真正的代价不是那一天的加班，而是…」。
改法是**把示范改成正向陈述**（「他们要的是一条能拿走的判断；故事只用来当证据」），
而不是再加一条禁令。迁移 v9 就是干这件事。

**② 清单体的序号分段，提示词管不住。**
职场稿的 5-7 条自测项，模型会把 2-3 条塞进同一个 `<p>`，或者写成
`1. 内容。为什么？\n因为…` 这种段内换行。已在 tail 里要求「每条独立成 `<p>`，
段首用 1./2. 序号」，仍然不稳。
**下一步**：在 `postProcess` 加一个确定性的「序号分段器」——把含有 `N. ` 的段落按序号切开。
这与星座的「相邻同星座段落合并」是同一类修法：**能用代码保证的形态，不要指望提示词**。

顺便修掉了一个通用缺陷：模型写清单时会把 markdown 的 `**…**` 混进 HTML，
在页面上变成满屏星号并把段落切碎。`html-sanitize.ts` 已加 `stripMarkdownBold()`，
成对还原成 `<strong>`，落单的直接删。
